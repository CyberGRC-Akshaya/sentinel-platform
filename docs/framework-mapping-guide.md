# Sentinel Framework Mapping Guide

## Purpose

The framework mapping library helps translate Sentinel findings into practical assurance relevance.

It supports:

- executive explanation
- audit/2LOD discussion
- remediation evidence requests
- consulting deliverables
- future framework mapping expansion

## Mapping fields

| Field | Meaning |
|---|---|
| Framework | Relevant standard, regulation, handbook, or assurance reference |
| Mapping Type | Whether the connection is examiner expectation, control relevance, assurance reliance, or good practice |
| Rationale | Why the finding matters under that framework |
| Expected Evidence | What evidence would normally help close the gap |

## Current domains

- Metrics Assurance
- Evidence Lineage
- Third-Party Risk
- Privacy / Data Protection
- SDLC / AI Governance
- Audit Evidence
- Identity & Access
- General Assurance

## Important control discipline

Do not claim exact regulatory citation unless independently verified.

Use language such as:

- aligned with
- relevant to
- supports expectations around
- consistent with examiner-style review of
- indicates a need to evidence

Avoid saying:

- mandated by
- required by exact section
- violates X

unless validated against the source framework.
