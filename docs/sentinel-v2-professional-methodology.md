# Sentinel v2.0 Professional Evidence Defensibility Methodology

## Positioning

Sentinel v2.0 is not positioned as a bank-ready SaaS platform.

It is positioned as a professional assurance workbench and consulting accelerator for evidence defensibility review.

## Review dimensions

Sentinel v2.0 scores evidence across seven defensibility dimensions:

| Dimension | Why it matters |
|---|---|
| Source Lineage | Evidence should tie back to a source system or authoritative artifact |
| Completeness | Evidence should cover the full population/scope or explain sampling |
| Calculation Integrity | Metrics should have clear numerator, denominator, and calculation logic |
| Review & Approval Evidence | Management conclusions should be reviewed and approved |
| Reporting Period Alignment | Evidence should match the reporting period or as-of date |
| Governance Traceability | Evidence should tie to tickets, policies, exceptions, risk acceptances, or control records |
| Data Handling & Privacy Boundary | Sensitive data evidence should show flow, access, retention, and protection boundaries |

## Output types

Sentinel v2.0 produces:

- evidence defensibility score
- item-level scorecards
- finding register
- evidence request list
- severity rationale
- framework mapping rationale
- HTML report
- JSON review result

## Correct use

Use Sentinel to accelerate:
- audit readiness
- IT metrics validation
- vendor evidence challenge
- privacy evidence review
- SDLC governance review
- AI governance readiness review
- IAM evidence review

## Important limitation

Sentinel outputs must be professionally reviewed before client delivery. The current engine is deterministic and rule-based; it supports expert review but does not replace it.
