# Sentinel Interview Story

## 60-Second Version

I built Sentinel as a hands-on assurance intelligence platform to demonstrate how technology can strengthen IT GRC, audit readiness, vendor risk, privacy, SDLC governance, IAM, and AI governance workflows.

The core problem I targeted is evidence defensibility. In regulated environments, teams often have evidence, but that evidence may not prove source lineage, denominator accuracy, reviewer approval, vendor reliance, data handling, or governance completion.

Sentinel reviews structured evidence packages and generates examiner-style findings, evidence gaps, challenge questions, remediation guidance, framework mapping rationale, finding registers, and HTML reports.

It is built with FastAPI, Next.js, Docker, GitHub, and n8n-based agent workflow planning. The project demonstrates not only documentation knowledge but practical product thinking, workflow automation, assurance design, and full-stack execution.

## 2-Minute Version

Sentinel came from a practical governance problem I have seen repeatedly: evidence exists, but it is not always defensible.

For example, a security metric may be reported to a committee, but the denominator may not reconcile to the source system. A vendor may provide SOC 2 evidence, but the review may not evaluate CUECs or data-flow boundaries. An AI-enabled release may go live without clear inventory, classification, approval, or monitoring evidence.

I built Sentinel to simulate the mindset of a strong 2LOD reviewer, internal auditor, or examiner. It challenges evidence packages and produces structured observations, evidence gaps, examiner-style questions, remediation guidance, framework mapping rationale, and a finding register.

Technically, I implemented it using FastAPI for the backend, Next.js for the frontend, Docker Compose for local deployment, GitHub for version control, and n8n/Google Workspace for the agent command center.

The project is intentionally business-facing. It is not just a coding project. It demonstrates how I think about regulated environments, audit defensibility, governance workflows, and practical risk remediation.
